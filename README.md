# GridTrax

## 功能

- **电影与电视剧实时热门榜**：刷新按钮左侧可切换豆瓣、TMDB 来源。豆瓣支持电影、电视剧实时热门榜前 10 名，保持豆瓣顺序；分别通过 TMDB `/search/movie`、`/search/tv` 按片名、原片名和年份匹配海报、简介及详情，分别展示有效的豆瓣与 TMDB 评分。TMDB 来源支持电影日榜、周榜切换，分别展示 `/trending/movie/day`、`/trending/movie/week` 首页，直接使用接口排名和影片资料；原名在标题下方以较小字号加粗展示，显示上映日期、中文类型、评分、海报及简介，缺失字段不显示。中文类型通过 `/genre/movie/list` 获取，内存缓存一天，类型接口失败不影响影片展示并支持重试。简介默认展示 4 行，可展开全部；支持进入影片详情及刷新重试，豆瓣条目未匹配时支持站内搜索。来源、电影或电视剧及日榜或周榜选项保存在网址参数中，详情返回和刷新后保留，切换不额外增加返回历史。
- **影视搜索与详情**：接入 TMDB，分页搜索电影、电视剧，查看海报、背景图、简介、评分及分季分集信息；请求超时或失败可重试，快速切换搜索不会显示旧结果，影片资料共用有容量和有效期限制的内存缓存。
- **电视剧分季详情**：各季可独立展开、收起，展示本季海报、首播日期、总集数、有效评分和独立简介；集数在展开后按需加载。单季作品的简介与整剧相同时不重复展示。
- **简介展开与收起**：电视剧整剧、每季和单集简介默认最多显示 3 行，按实际排版是否超过 3 行显示“展开全文”，不按字数判断；展开后可收起，窗口宽度变化时自动重新判断。电影简介目前直接显示全文。
- **观看状态管理**：支持在看、想看、看过、搁置和抛弃，记录电影及电视剧各季的观看状态和单集进度；点击集数切换已看，长按或右键可选择“看到这里”批量标记。
- **集数分页与排序**：在看卡片和电视剧详情页的每季集数均每页展示 18 集，支持上一页、下一页和正序、倒序排列；分页不影响整季观看进度统计。
- **移动端标题列表**：存在有效单集短标题时，可在集数网格和标题列表之间切换。
- **单集详情视图**：电视剧详情页可切换单集详情，查看短标题、首播日期、本集时长和简介，缺失字段及无效时长不显示。上方左侧为集数按钮，右侧为标题和日期、时长，下方通栏展示首行缩进的简介；仍支持分页、排序及观看标记，切换视图保留当前页码和顺序，阅读或展开简介不会改变观看记录。
- **追踪筛选与排序**：支持按全部、电视剧、电影筛选，以及按最近互动、名称、TMDB 评分排序。
- **影片网格**：除在看外，各板块的网格视图每页展示 15 部影片；移动端每行 3 部，桌面端每行 5 部，展示海报、年份、电影或季标签及 TMDB 评分。电视剧年份取对应季的首播年份，不使用整部剧的首播年份。
- **看过时间线**：可在网格和时间线之间切换，并记住所选视图；切回网格保留筛选和页码。时间线展示全部看过记录，按最近操作时间倒序分月、分日，年月栏滚动吸顶并随月份自动替换。同一天的影片在窄屏、中等宽度、宽屏下分别按 1、2、3 列排列。
- **明暗主题**：提供多款暗色主题和 Sunlit Mint 明亮主题，支持切换并记住选择。
- **本地存储与备份**：观看记录保存在当前浏览器的 LocalStorage 中，保存失败会提示并支持重试；支持 JSON 导入、导出和旧版备份兼容。导入前校验文件并确认覆盖，保留一份本地恢复快照，并显示最近生成备份的时间；备份不包含账号信息或 API Token，不同设备间通过 JSON 文件手动迁移。本地恢复快照不能替代下载的 JSON 备份。
- **浏览位置恢复**：新进详情页从顶部开始，通过浏览器历史返回时恢复追踪页的网格页码和滚动位置；右下角支持一键回到顶部。
- **响应式布局**：适配手机和电脑，导航栏直接提供搜索、数据备份和主题切换入口。

## 部署

项目使用 Cloudflare Pages 部署：React SPA 提供界面，仓库内的 Pages Functions 转发豆瓣榜单，无需单独部署后端。

### 构建配置

在 Cloudflare 控制台创建 Pages 项目并连接 Git 仓库，设置以下参数：

| 配置项 | 值 |
| --- | --- |
| 构建命令 | `npm run build` |
| 构建输出目录 | `dist` |
| 项目根目录 | 仓库根目录 |
| Node.js | 22.12.0 或更高版本 |

保留根目录的 `wrangler.jsonc`，其中已将 `pages_build_output_dir` 配置为 `dist`。

同时保留 `functions/` 和 `server/` 目录，Pages 连接 Git 仓库部署时会自动构建电影和电视剧榜单接口 `/api/hot/movies`、`/api/hot/tv`。`public/_routes.json` 限定只有这两个路径调用 Functions，其他页面仍按静态资源提供。仅上传 `dist` 静态文件不能包含榜单服务。

本地安装依赖后使用 `npm run dev`，Vite 会复用榜单服务逻辑；`vite preview` 仅预览静态构建，不提供榜单接口。

### TMDB Token

在 Pages 对应部署环境的构建环境变量中添加 TMDB 的 **API Read Access Token**：

```env
VITE_TMDB_BEARER=your_tmdb_read_access_token
```

- 使用完整的 Read Access Token，不是 API Key，也不要添加 `Bearer ` 前缀。
- 无需提交 `.env.local`，网页中也不提供 Token 设置入口。
- 如需预览部署，应为预览环境配置同名变量。
- 修改 Token 后需要重新构建部署，才能更新前端产物。

### 部署与更新

保存配置并部署。后续将代码推送至 Pages 绑定的部署分支，即可触发构建更新。

注意事项：

- `VITE_` 变量会被嵌入浏览器可下载的前端代码，并非服务端秘密。不要将 `.env.local` 或真实 Token 提交到公开仓库。
- 搜索、详情和海报由浏览器直接请求 TMDB，静态部署不会代理这些请求，访问环境需要能够连接 TMDB。
- 豆瓣榜单由服务端匿名请求，不需要配置或提交个人 Cookie。成功结果缓存 5 分钟，刷新可能仍返回缓存；“获取于”是抓取时间，不是豆瓣更新时间。此接口并非稳定开放 API，如豆瓣限制访问或更改结构，页面会提示重试，不会展示伪造的榜单数据。
- 热门榜分别标注豆瓣和 TMDB 评分；详情和追踪页继续使用 TMDB 评分，两者不会混用，也不会将浏览榜单操作写入观看记录。
- 观看记录仅保存在当前浏览器，清除站点数据会删除记录，请定期导出 JSON 备份。
